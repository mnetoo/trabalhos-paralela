- Protótipo Exigido da Função Paralela:
    void ParallelPrefixSumPth( volatile TYPE *Vec, 
                               long nTotalElmts, 
                               long chunkSize,
                               int nThreads );

- Estruturas Globais:
    - PartialSum: vetor auxiliar global de tamanho MAX_THREADS.
    - Sincronização: barreiras (pthread_barrier_t) e/ou contadores atômicos (atomic_int).
    - ThreadPool: arrays de pthread_t e pthread_attr_t, além da flag 'static int initialized'.

2. INICIALIZAÇÃO DO THREADPOOL E AFINIDADE DE CORE FÍSICO
-------------------------------------------------------------------
Para evitar migração de threads pelo SO e garantir cache L1/L2 dedicado em cada núcleo físico:

- Mapeamento de Núcleos Físicos:
    - Obter a topologia da CPU do Lab 4 (via 'lscpu -e' ou 'lstopo') para identificar os IDs dos NÚCLEOS FÍSICOS.
    - Definir um vetor estático de mapeamento priorizando núcleos físicos distintos antes de usar Hyper-Threading:
      int physical_core_map[8] = {0, 1, 2, 3, 4, 5, 6, 7}; // Ajustar IDs conforme topologia real do Lab 4

- Na primeira execução da função (!initialized):
  1. Inicializar as barreiras de sincronização.
  2. Para cada worker thread (i de 1 até nThreads-1):
     - Atribuir o core físico exclusivo: core_id = physical_core_map[i];
     - Configurar a máscara cpuset via CPU_ZERO(&cpuset) e CPU_SET(core_id, &cpuset).
     - Aplicar no atributo: pthread_attr_setaffinity_np(&attr[i], sizeof(cpu_set_t), &cpuset).
     - Criar a thread associada ao pool com os atributos definidos.
  3. Definir initialized = 1.

3. LINHA DE COMANDO E GERENCIAMENTO DE CHUNKS
-------------------------------------------------------------------
- Sintaxe de Execução:
    ./prefixSumPth <nTotalElements> <nThreads> <chunkSize> [-v]

- Lógica do chunkSize:
    - Se chunkSize > 0: Cada thread percorre o vetor em blocos do tamanho informado 
      procurando manter os dados aquecidos na memória cache.
    - Se chunkSize == 0: Cada thread opera em um único bloco contínuo (stride estático):
      nElements = (nTotalElements + nThreads - 1) / nThreads.

- Parâmetro -v (Verificação Opcional):
    - Requer alocar e copiar o vetor inicial sequencialmente (InitVector) na main.
    - Se -v for informado, chama ao final:
      verifyPrefixSum(InitVector, Vec, nTotalElements);

4. IMPLEMENTAÇÃO DO KERNEL COM 2 BARREIRAS (OTIMIZAÇÃO ATÔMICA)
-------------------------------------------------------------------
Substituição da 3ª barreira do modelo clássico por sinalização atômica leve:

Mecanismo de Controle:
  - atomic_int threads_completed = 0;
  - Barreira 1 (Pool): Libera a execução das threads trabalhadoras.
  - Barreira 2 (Algoritmo): Aguarda todas gravarem em PartialSum.
  - Conclusão da Fase 2:
    - Workers (threads 1..nThreads-1): Ao concluírem, executam:
      atomic_fetch_add(&threads_completed, 1);
    - Thread 0 (Main): Aguarda as workers terminarem via spin suave:
      while (atomic_load(&threads_completed) < nThreads - 1) { /* spin */ }

Fluxo do Kernel da Thread (Worker):
  while (true):
    1. pthread_barrier_wait(&pool_barrier); // BARREIRA 1 (Início do bloco)

    2. FASE 1 (Soma Parcial Pré-Barreira):
       - Lê sua fração do vetor Vec (respeitando o chunkSize).
       - Armazena a soma calculada da sua faixa em PartialSum[myIndex].

    3. pthread_barrier_wait(&algo_barrier); // BARREIRA 2 (Somas parciais salvas)

    4. FASE 2 (Soma de Prefixos In-Place Pós-Barreira):
       - Lê PartialSum[0...myIndex-1] e calcula o offset local myPrefixSum.
       - Atualiza o vetor Vec IN-PLACE diretamente acumulando a soma e myPrefixSum.

    5. SINALIZAÇÃO DE TÉRMINO:
       - Se myIndex != 0: executa atomic_fetch_add(&threads_completed, 1).
       - Se myIndex == 0: aguarda todas concluírem e retorna a chamada para o main.
